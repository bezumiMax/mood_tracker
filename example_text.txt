Представляет собой набор одинаковых квадратных костяшек с нанесёнными числами, заключённых в квадратную коробку. Длина стороны коробки в четыре раза больше длины стороны костяшек для набора из 15 элементов, соответственно в коробке остаётся незаполненным одно квадратное поле. Цель игры – перемещая костяшки по коробке, добиться упорядочивания их по номерам, желательно сделав как можно меньше перемещений. Целью данной работы является разработка программной версии игры «Пятнашки» с голосовым управлением. Игра «Пятнашки» с голосовым управлением (далее - игра) – программный продукт, предназначенный для отдыха и развития логического мышления. Постановка и анализ задачи Назначение разработки Игра должна быть разработана в виде смартапа. Смартап – это мультимодальное приложение, которое дает пользователю красивый интерфейс и множество способов взаимодействия: голосом, касанием, текстовым вводом, пультом и даже виртуальным геймпадом. Смартапом можно управлять с помощью семейства виртуальных ассистентов Салют. Эти ассистенты применяются в мобильных приложениях и умных устройствах Сбера. Например, в приложении СберБанк Онлайн, в TV-приставке SberBox, а также в смарт-дисплее SberPortal. Игра должна обеспечивать следующие функции: запуск/перезапуск игровой ситуации; управление перемещением пазлов игры с помощью доступных для исполнительного устройства органов управления (например, манипулятор «Мышь», сенсорный экран); подсчет количества перемещений пазлов; управление запуском/перезапуском и перемещением пазлов с помощью голосовых команд. Помимо отображения элементов управления, компонент «Puzzles» создает объект виртуального ассистента (функция  initializeAssistant  вызывается в конструкторе класса). В объекте ассистента регистрируются методы: getStateForAssistant  – для формирования объекта с информацией о состоянии приложения; dispatchAssistantAction  – событие  onData  виртуального ассистента, вызывается при получении новых данных от виртуального ассистента. Таким образом, взаимодействие с виртуальным ассистентом выполняется через эти два метода. Когда приложение изменило состояние, то вызывается  getStateForAssistant  и данные передаются виртуальному ассистенту, а когда в виртуальном ассистенте изменилось состояние, то вызывается метод  dispatchAssistantAction . Объект ( stateAssist ), формируемый методом  getStateForAssistant  для передачи информации о состоянии приложения виртуальному ассистенту, имеет следующую структуру: const stateAssist = { item_selector: { items: […]  }}; где  items  - это массив свойств пазлов, для которых в текущем состоянии игры доступно перемещение. Метод  dispatchAssistantAction  фактически реализует реакцию приложения на голосовые команды, поданные виртуальному ассистенту: «on_click_puzzle» - команда нажатия на пазл, формируется на стороне виртуального ассистента, когда игрок произносит цифры от 0 до 15. По этой команде на стороне  front - end  формируется действие «ACTION_MOVE»; «reset_game» - команда перезапуска игры, формируется на стороне виртуального ассистента, когда игрок произносит фразу «Новая игра». По этой команде на стороне  front - end  формируется действие «ACTION_NEW_GAME»; «close_game» - команда выхода из игры, формируется на стороне виртуального ассистента, когда игрок произносит фразу «Выход». По этой команде на стороне  front - end  закрывается ассистент ( this.assistant.close(); ). Редуктор и действия Библиотека «redux» позволяет организовать простые и удобные механизмы управления состоянием как всего  React -приложения, так и отдельных его компонентов.  Принцип работы библиотеки «redux» поясняется рисунком 8. Когда в приложении происходит какое-то действие, то это действие обрабатывается редуктором. Редуктор в ответ на каждое действия как-то изменяет состояние приложения и сохраняет это состояние в объекте-хранилище. Состояние приложения (объект-хранилище) доступен всем  React -компонентам только для чтения. Таким образом, компоненты имеют доступ к состоянию всего приложения, а изменяют его путем формирования определенных действий. В нашем приложении определено всего два типа действий (см. «actions.js»): « ACTION _ MOVE » - определяет перемещение пазла. Объект этого действия создается функций  doMove . Объект содержит два свойства: тип действия ( type ) и координаты перемещаемого пазла ( payload ); « ACTION _ NEW _ GAME » - определяет перезапуск игры. Объект этого действия создается функций  doNewGame . Объект содержит два свойства: тип действия ( type ) и свойство  payload , которое не заполняется ( null ); Рисунок 8 – Принцип работы библиотеки «redux» Алгоритмы формирования перечисленных действий были описаны ранее. Редуктор реализован в файле «reducers.js». Редуктором является функция следующего вида: const rootReducer = (state, action) =&gt; { …… return state;}; На вход функции подается текущее состояние приложения и действие, которое должно изменить это состояние. Функция меняет текущее состояние приложения в соответствие с действием и возвращает новое состояние приложения. Состояние приложения Если браузер поддерживает локальное хранилище, то текущее состояние приложения будет сохраняться в  localStorage  и восстанавливаться из localStorage при перезагрузке приложения. Для работы с локальным хранилищем реализованы функции  loadState() ,  saveState()  и  clearState() , в файле «localStorage.js». Функции, соответственно, предназначены для загрузки, сохранения и очистки состояния приложения. Объект-хранилище ( store ) состояния приложения создается функций  createStore  импортированной из пакета «redux» (см. файл «index.js»). Входными параметрами этой функции является редуктор и исходное состояние приложения. Для того чтобы иметь возможность сохранять каждое изменение состояния приложения, в локальном хранилище регистрируем обработчик события об изменении состояния с помощью метода  store.subscribe() . Для получения состояния приложения из объекта-хранилища нужно вызвать метод: const state = store.getState(); Объект состояния приложения имеет следующий набор свойств: grid  – массив со свойствами 16-ти пазлов; moves  – счетчик ходов; started  – признак начала игры; win  – признак победы в игре. Как было описано ранее, состояние приложения изменяется редуктором. Если произошло действие « ACTION _ NEW _ GAME », то сбрасывается признак начала игры ( started ), обнуляется счетчик ходов ( moves ), пазлы в массиве  grid  расставляются в случайные позиции и выполняется расчет признака победы в игре ( win ). Если произошло действие « ACTION _ MOVE », то выполняется перемещение пазла на пустую позицию (если это возможно), устанавливается признак начала игры, увеличивается на один количество ходов и выполняется расчет признака победы в игре ( win ). Функции по управлению размещением пазлов и изменению позиций пазлов определены в файлах «gridGenerator.js», «gridFinder.js» и «gridMove.js».
